# 龙门架实时受力分析

## 怎么打开

**双击 `start.bat`**，浏览器会自动打开。用完直接关掉那个黑窗口。

> 用摄像头必须走 `start.bat`。浏览器只允许网页在 `http://` 下调用摄像头，
> 直接双击 `index.html` 会打不开摄像头（纯鼠标模拟仍然可以）。

识别用的模型全部已经下到本地（`lib/`、`models/`，约 25MB），**教室断网也能用**。

# 现场使用步骤

## 一、准备（只做一次）

1. **摄像头架三脚架，正对龙门架**，尽量退远。位置固定好，**挪动过就要重新标定**。
2. **称体重**，课上填进右侧滑条。
3. 只有打算用「绿卡识别」滑轮时才需要贴卡：**两张荧光绿卡**，哑光纸、加黑边，
   贴在滑轮小车**正对镜头**的侧面并保持竖直。卡越大越好认（20cm × 10cm 起步），
   太小的话在画面里只有十几个像素，形状过滤会直接把它扔掉。

> **不需要量任何尺寸。** 按「正对拍摄、无透视畸变」处理时，画面到现实是一个
> 相似变换（缩放 + 旋转 + 平移），而相似变换**保角**——缩放比例在角度里会完全约掉。
> 受力只跟绳的方向有关，所以跨度、高度这些数字根本不进入计算。
> （代价是摄像头必须尽量正对；斜着拍会有透视畸变，这套算法不做校正。）

## 二、标定（**必做**，每次挪动摄像头后都要重做）

> 标定是把画面像素换算成现实米数的唯一途径。**没标定的话人也识别不了**，
> 面板上那条橙色横幅就是提醒这件事，标定完会变成绿色的「✓ 标定完成」。

1. 右侧「数据来源」点 **摄像头**，允许浏览器使用摄像头。
2. 点 **开始标定**，然后**在下方摄像头画面上**依次点 4 个点（点在画面里，不是点按钮）：

   ① 横梁左端 → ② 横梁右端 → ③ 左边那个滑轮 → ④ 右边那个滑轮

   每点一下，横幅上的计数会从 0/4 走到 4/4，画面上会留下带编号的圆点。
3. 点完 ①②，画面上会出现一条**青色虚线**贴着横梁——如果它没贴住真实横梁，说明点歪了，重来。

前两个点只用来告诉软件「水平方向在画面里是哪个方向」，顺带把摄像头的侧倾转正。

## 三、滑轮位置：点选 or 自动

面板上「滑轮位置怎么定」有两个选项：

- **画面上点选**（默认，推荐）——标定的 ③④ 就是在点滑轮。**绿卡完全不用贴。**
  滑轮被学生推动之后，点一下「滑轮动了？只重点这两个滑轮」，重新点两下即可，
  横梁的标定不用重做。也可以直接在受力图上用鼠标微调。
- **绿卡识别**——滑轮也交给摄像头认，适合滑轮会频繁移动的场合。选了才需要下面的调参。

两种模式下**人都是摄像头识别的**，这才是真正需要实时跟踪的部分。

## 四、调绿卡识别（只有选「绿卡识别」才需要）

勾上 **显示绿色识别掩码**，画面上会用绿色高亮出「软件认为是绿色的像素」。
目标很简单：**只有两张卡是亮的**。

| 现象 | 调哪个 |
|---|---|
| 卡片不亮 / 只亮一半 | 调低「饱和度下限 S」或「亮度下限 V」 |
| 一片乱七八糟都亮 | 调高「饱和度下限 S」 |
| 亮的是别的绿东西 | 收窄「色相 H」上下限 |
| 卡认出来了但框不稳 | 调高「最小面积」或「矩形填充度下限」 |

灯光变了（开灯/关灯/拉窗帘）可能要微调，所以这几个滑条是常驻的。

**掩码全黑、一张卡都不亮？先看标定横幅是不是绿色的。** 没标定的话识别根本不会启动。

## 五、上课

标定好之后，把「显示摄像头画面」取消勾选，画面只剩受力图，投影出去就行。
滑轮和人一动，箭头和数值实时跟着变。

## 识别不到怎么办

画面左上角会直接写出缺了什么（例如「没识别到：滑轮2、人（识别到 1/2）」），
此时**保持上一次的位置**不会乱跳。常见原因：

- 绿卡被手挡住、或转得太侧 → 让开 / 摆正
- 灯光直射反光过曝 → 换哑光纸，或调低「亮度下限 V」
- 人离画面边缘太近，MediaPipe 认不出躯干 → 往画面中间站

## 精度能到多少

用合成画面测过：摄像头侧倾 7° 时，角度还原**精确到小数点后 3 位**；
把拍摄距离放大 3 倍，算出来的角度和张力**一个数字都不变**（缩放确实约掉了）。

真实使用时主要误差来自两处，都和算法无关：

- **摄像头没正对**。斜着拍会有透视畸变，这套算法按无透视处理，不做校正。越正对越准。
- **人前后晃出了那个竖直平面**。摄像头架远一点能明显改善。

模式 B 会把左右两侧**各自独立算出的相互作用力**都显示出来。理论上它们必须相等，
两个数差多少就是当前的测量误差；差超过 25% 会直接提示。这个对照本身就很值得给学生看。

## 两个模式

**模式 A · 一人两绳（力的分解）**
拖动两个滑轮或者人。两绳张力由平衡条件解出：

```
T₁ = G·sinθ₂ / sin(θ₁+θ₂)
T₂ = G·sinθ₁ / sin(θ₁+θ₂)
```

把人往上拖到接近横梁，绳趋近水平，张力会迅速超过体重好几倍——这是这个模式最值得讲的一幕。

**模式 B · 两人互拉（相互作用力）**
拖动左侧学生。每个人竖直方向 `T·cosθ = G`、水平方向 `T·sinθ = F`，于是 `F = G·tanθ`。
牛顿第三定律要求两人受到的 F 相等，所以：

```
G₁·tanθ₁ = G₂·tanθ₂
```

把两人体重调开（比如 90kg 对 15kg），会看到轻的那个摆到 46°、重的才 10°。

## 画面上「绳」和「力」是两回事

- **绳**：浅灰色细线，从滑轮挂钩画到**手**为止。手以下那截绳和手臂重叠，画出来会被看成多长了一条手臂，所以省略。
- **拉力**：红/橙色粗箭头，画在重心（⊕）上，方向沿绳。
- 绳的汇合点就取在重心上（`app.js` 的 `COM_BELOW = 0`），所以**拉力箭头、手臂、绳三者共线**，
  视觉上是从重心一路延伸到滑轮的一条线；这也正是质点模型「各力共点」该有的样子。
- 角度弧线不画（数值在右侧面板里）。平行四边形和力的数值固定显示。

## 模型假设

- 人视为质点，各力平移到重心处合成
- 绳不可伸长、无质量，滑轮水平方向无摩擦
- 模式 B 中两人之间的相互作用力沿水平方向；为此右侧绳长会自动配平，使两人挂点等高
- 绳只能拉不能推，模式 A 中出现负张力时会提示「此位置无法平衡」

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构 |
| `style.css` | 样式 |
| `physics.js` | **只有受力计算**，两个模式各一个函数 |
| `app.js` | 画布绘制、鼠标交互、把识别结果接进来 |
| `vision.js` | 摄像头识别：标定（单应性变换）、绿卡检测、MediaPipe 姿态 |
| `wire.js` | 摄像头这块的界面接线：标定流程、调参滑条、画面叠加层 |
| `lib/`、`models/` | MediaPipe 的运行时和模型，已本地化，勿删 |

改参数：`app.js` 顶部的 `state`。**横梁跨度 `span` 和高度 `beamY` 在这里改**
（界面上没有滑条，按你现场的实际尺寸设一次就行）；体重在界面上调。
改人体比例：`app.js` 里的 `BODY`（身高约 1.32m，手臂 0.52m）。
